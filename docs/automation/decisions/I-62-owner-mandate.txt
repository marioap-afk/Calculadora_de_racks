======================================================================
GOAL
======================================================================

Remove unnecessary provider/session coupling from I-61.

A RackCad initiative must be able to bind execution roles to different
AI providers/models/runtimes according to verified capability rather than
hard-coded assumptions such as:

Claude = Principal

Codex = Reviewer

The protocol must remain provider-agnostic.

======================================================================
PRIMARY ROLES
======================================================================

Formalize provider-independent roles:

PRINCIPAL_COORDINATOR
ARCHITECT
EXECUTION_CONTROLLER
WORKER
REVIEWER

Possibly others only if Discovery proves a need.

Role semantics are stable.

Provider/model bindings are runtime decisions.

======================================================================
ROLE BINDING
======================================================================

At initiative/session bootstrap, resolve bindings based on observable facts.

Inputs may include:

- available providers;
- available models;
- capacity level;
- effort capabilities;
- token/quota availability when observable;
- cost policy;
- task risk;
- horizon;
- independence requirement;
- CLI/runtime availability;
- authentication;
- tool access;
- computer-use capability;
- repo access.

Do NOT infer unavailable facts.

Fail closed when a required capability cannot be accredited.

======================================================================

- roles;

- delegations;
- handoffs;
- verification;
- exact-SHA;
- STOP;
- retry budgets;
- ownership/custody;
- evidence.

Provider adapters/catalogs own:

- executable / CLI;
- invocation syntax;
- API details;
- authentication;
- model names;
- effort flags;
- session introspection;
- output parsing;
- computer-use specifics;
- service tier.

No provider-specific field should leak into core schemas unless represented
through an explicit adapter metadata boundary.
