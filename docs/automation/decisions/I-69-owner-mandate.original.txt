IDENTITY VS DISPLAY NAME
======================================================================

Esta decisión es material.

Determinar si actualmente:

Option identity
=
description string

o si existe:

StableId / PieceId / Code
+
DisplayName / Description

Preferencia arquitectónica:

Stable identity
!=
display description

pero NO refactorizar si no es necesario para el cambio solicitado.

Si las descripciones actuales son identidad persistida:

- no renombrar strings a ciegas;
- caracterizar payload legacy;
- definir compatibilidad;
- decidir si se requiere alias/mapping/migration.

Si existe ID estable separado:

- cambiar DisplayName sin alterar identidad.
