Para cada paso registra en "commands" las líneas de comando exactas que ejecutaste, en orden; en "ok", si el paso se completó; en "values", los pares clave/valor que pide el paso, con las claves exactas indicadas; en "error", el error exacto si falló (null si no). Ningún paso admite `git fetch`, `git pull` ni otro comando que escriba en el repositorio.

1. Ejecutar `ver` y `echo %ComSpec%`. Claves: "ver" (la salida de ver) y "ComSpec" (la salida de echo).
2. Ejecutar `git rev-parse HEAD`. Clave: "HEAD".
3. Ejecutar `git diff --name-only {{BASE_SHA}}..{{HEAD_SHA}}`. Un par por línea de la salida, en el orden en que sale, con la clave "path".
4. Ejecutar otra vez exactamente el mismo comando del paso 3. Un par por línea con la clave "path", como en el paso 3, y además la clave "identical" con "yes" si la salida es idéntica a la del paso 3 o "no" si no lo es.
5. Para cada archivo de esta lista: {{HASH_FILES}}. Ejecutar `git hash-object <archivo>` y `git rev-parse HEAD:<archivo>`. Claves: "hash-object:<archivo>" y "rev-parse:<archivo>", con <archivo> escrito exactamente como en la lista.
6. Para cada archivo de la misma lista, ejecutar `certutil -hashfile <archivo> SHA256`. Clave: "sha256:<archivo>", con el SHA-256 en hexadecimal.

9. Lecturas de Git de la comprobación Identity. Ejecutar `git rev-parse --abbrev-ref HEAD` (clave "branch"), `git rev-parse --show-toplevel` (clave "toplevel"), `git rev-parse refs/remotes/origin/{{BRANCH}}` (clave "origin-branch") y `git merge-base --is-ancestor {{BASE_SHA}} {{HEAD_SHA}}` (clave "is-ancestor": "yes" si su código de salida es 0, "no" si es 1).
10. Lecturas de Git de la comprobación Remote. Ejecutar `git ls-remote origin refs/heads/{{BRANCH}}` (clave "ls-remote:branch", con el SHA de la salida), `git ls-remote origin refs/heads/main` (clave "ls-remote:main", con el SHA de la salida) y `git rev-parse refs/remotes/origin/main` (clave "origin-main").
11. Lecturas de Git de la comprobación CleanTree. Ejecutar `git status --porcelain` (clave "status", con la salida completa, o cadena vacía si no hay salida), `git status --porcelain --ignored` (clave "status-ignored", igual) y `git check-ignore -v --no-index {{IGNORE_PATH}}` (clave "check-ignore", con la salida completa o cadena vacía, y clave "check-ignore-matched": "yes" si su código de salida es 0, "no" si es 1).
12. Lecturas de Git de la comprobación Trailer. Ejecutar `git rev-list --reverse {{BASE_SHA}}..{{HEAD_SHA}}`: un par por línea de la salida, en orden, con la clave "commit". Para cada uno de esos commits, ejecutar `git log -1 --format=%(trailers:key=Co-Authored-By,valueonly) <commit>` y registrar la clave "trailer:<commit>" con las líneas no vacías de la salida unidas por " | " (cadena vacía si no hay ninguna).
