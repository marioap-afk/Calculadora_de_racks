### 3. Causa 2: la inexistencia se prueba, no se infiere

`git cat-file --batch-check`, con el entorno endurecido heredado de A-11/A-4, consulta el candidato por entrada estándar. El resultado se clasifica en exactamente uno de tres estados:

| Estado | Condición | Efecto |
|---|---|---|
| `MISSING` | código 0, stderr vacío y salida exactamente `<sha> missing` + LF | prueba la inexistencia |
| `EXISTS` | código 0, stderr vacío y salida exactamente `<sha> <tipo> <tamaño>` + LF | `MUTATED_SHA_EXISTS`, control FAIL |
| `ERROR` | todo lo demás | `GIT_OBJECT_QUERY_FAILED`, fallo cerrado |

`ERROR` incluye: error de proceso, código de retorno distinto de 0, stderr con cualquier contenido, salida malformada, vacía, parcial o con texto adicional, respuesta sobre otro objeto, tiempo agotado y ejecutable que no se puede iniciar. Un fallo del proceso nunca se interpreta como `missing`.

### 4. Garantía restaurada

`ControlResult = PASS` exige recorrer `verify` sin ningún motivo de fallo. Cada comprobación que falla registra su motivo, y un solo motivo impide PASS. Por tanto no hay PASS posible si:

- la validez del relevo contra el esquema es desconocida o falsa (§ 2);
- el éxito de la consulta al repositorio es desconocido (§ 3);
- la existencia del objeto es ambigua (§ 3);
- una entrada requerida no se puede leer (`*_UNREADABLE`);
- existe una segunda mutación (`MUTATION_NOT_ONLY_CURRENT_SHA`, `MUTATION_BYTES_NOT_EXACT`, `MUTATION_KEY_ORDER_CHANGED`).

Los errores de la consulta de objeto se declaran además `FailClosed = true`.
